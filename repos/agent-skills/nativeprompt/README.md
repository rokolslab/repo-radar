# nativeprompt

> https://github.com/edvardgrishin27/nativeprompt

## Кратко

`nativeprompt` — Python CLI и agent skill для адаптации одного и того же пользовательского запроса под конкретный coding-agent/model family. Инструмент анализирует prompt с учетом опубликованных рекомендаций вендора, показывает, какое правило сработало, и предлагает более подходящую форму запуска задачи.

Проект ориентирован именно на agentic CLI: Claude Code, Codex, Gemini CLI, Grok Build, Qwen Code и Kimi CLI. Для Claude Code и Codex заявлены model-specific prompting rules; для остальных семейств — в основном рекомендации по harness/workflow без выдуманных «официальных» правил.

## Какую проблему решает

Хороший prompt для одного семейства моделей не обязательно хорош для другого. Например, инструкции вида «think step by step», агрессивные `MUST/CRITICAL`, повторение ограничений или чрезмерное scaffolding могут по-разному влиять на Claude и GPT/Codex.

`nativeprompt` пытается сделать этот слой явным:

```text
исходный prompt
      │
      ▼
 nativeprompt
      │
      ├── определение модели/CLI
      ├── проверка по правилам вендора
      ├── объяснение каждого замечания
      └── рекомендация по форме запуска
      │
      ▼
prompt, адаптированный под текущий agent CLI
```

## Основные возможности

- определение текущего model family и источника этого определения;
- анализ prompt по правилам, привязанным к официальной документации вендоров;
- объяснение каждого изменения или предупреждения со ссылкой на источник;
- рекомендации по способу запуска задачи в Claude Code и Codex;
- JSON-вывод для интеграции с другими инструментами;
- `update --diff` для сравнения сохраненных правил с изменившейся документацией вендоров;
- работа offline для основного анализа;
- нулевые runtime-зависимости: используется Python stdlib;
- режим Claude Code skill;
- `UserPromptSubmit` hook для автоматической обработки каждого запроса в Claude Code.

## Как можно использовать

### 1. Проверка сложных prompts перед запуском

Перед передачей большой инженерной задачи Codex или Claude Code:

```text
задача
  │
  ▼
nativeprompt
  │
  ▼
проверенный prompt + объяснение
  │
  ▼
Codex / Claude Code
```

Полезно, если один и тот же стиль prompts используется с разными агентами.

### 2. Обучение prompt engineering на реальных правилах

Инструмент интересен не только как rewriter. Он показывает, почему конкретная конструкция считается удачной или неудачной для определенного семейства моделей. Это позволяет постепенно выработать собственный стиль постановки задач.

### 3. Preflight-слой перед engineering skills

Можно использовать перед `mattpocock/skills` или собственными workflow:

```text
идея / задача
     │
     ▼
nativeprompt
     │
     ▼
grill / to-spec / implement
```

`nativeprompt` отвечает за форму запроса, а engineering skills — за процесс разработки.

### 4. Проверка prompts для Codex

Для Codex особенно полезен режим явного указания модели, поскольку сам проект признает ограничения автоматического определения активной Codex-конфигурации.

## Сильные стороны

1. Правила не скрыты: можно открыть источник и проверить аргументацию.
2. Не пытается выдавать общие prompt-эвристики за рекомендации конкретного вендора.
3. Очень легкий runtime: Python stdlib, без API key для базовой работы.
4. Хорошо подходит для сравнения Claude Code и Codex.
5. Может использоваться как учебный инструмент, а не только как автоматический rewriter.
6. Есть механизм контроля устаревания правил.

## Ограничения и риски

1. Проект очень молодой, поэтому поведение и интерфейс могут быстро меняться.
2. Полнота поддержки разных CLI различается: основные model-specific правила сосредоточены на Anthropic/OpenAI.
3. Автоматическое определение Codex/Claude конфигурации имеет документированные пробелы.
4. Любой prompt-rewriter может ухудшить хороший специализированный prompt, поэтому изменения стоит просматривать, а не применять слепо.
5. Vendor guidance меняется; механизм `update` снижает риск устаревания, но не устраняет необходимость проверки.

1. Установить `nativeprompt` из PyPI или локального checkout.
2. Взять 5–10 реальных prompts, ранее использованных с Codex.
3. Сравнить исходный вариант с рекомендациями `nativeprompt`.
4. Те же prompts проверить в Claude Code profile.
5. Оценить не только красоту переписывания, но и фактическое качество выполнения задачи агентом.

## Решение
