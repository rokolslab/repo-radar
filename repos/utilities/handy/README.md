# Handy

> https://github.com/cjpais/Handy

## Кратко

`Handy` — бесплатное open-source desktop-приложение для локального speech-to-text. Пользователь нажимает глобальный хоткей, диктует текст, а приложение распознаёт речь на компьютере и вставляет результат в текущее поле ввода. Аудио не требуется отправлять в облачный API.

Проект ориентирован на простую системную диктовку: не отдельный чат и не специальный редактор, а голосовой ввод практически в любое приложение.

## Какую проблему решает

Обычная схема облачной диктовки выглядит так:

```text
микрофон
   │
   ▼
облачный STT
   │
   ▼
текст
```

Handy переносит распознавание на локальную машину:

```text
микрофон
   │
   ▼
Handy
   │
   ├── VAD / Silero
   │
   ├── Whisper
   │     или
   └── Parakeet V3
          │
          ▼
    локальный текст
          │
          ▼
 активное поле ввода
```

Это уменьшает зависимость от сети и внешних сервисов и делает голосовой ввод пригодным для приватных рабочих данных.

## Основные возможности

- глобальный configurable shortcut;
- режим start/stop и push-to-talk;
- автоматическая фильтрация тишины через VAD;
- локальные Whisper-модели Small / Medium / Turbo / Large;
- GPU acceleration для Whisper там, где она доступна;
- Parakeet V3 как CPU-oriented альтернативный backend;
- автоматическое определение языка у Parakeet V3;
- вставка распознанного текста непосредственно в активное приложение;
- Windows, macOS и Linux;
- CLI-команды для управления уже запущенным экземпляром;
- transcript history и dictionary;
- возможность внешнего запуска из hotkey managers и desktop automation.

## Архитектура

Handy построен на Tauri:

```text
React + TypeScript
       │
       ▼
   Tauri shell
       │
       ▼
      Rust
       │
       ├── audio / cpal
       ├── VAD / vad-rs
       ├── Whisper / transcribe-cpp
       ├── Parakeet / transcribe-rs
       ├── keyboard events / rdev
       └── text injection / OS integration
```

Основной язык репозитория — Rust. UI реализован на React/TypeScript.

## Поддерживаемые платформы

- Windows x64;
- macOS Intel;
- macOS Apple Silicon;
- Linux x64.

Для Windows доступен обычный release installer и сторонний пакет Winget:

```powershell
winget install cjpais.Handy
```

На macOS существует Homebrew cask.

Linux поддерживается, но именно там сейчас больше platform-specific ограничений, особенно на Wayland.

## CLI и автоматизация

Запущенным приложением можно управлять через CLI:

```bash
handy --toggle-transcription
handy --toggle-post-process
handy --cancel
```

Также есть startup flags:

```bash
handy --start-hidden
handy --no-tray
handy --debug
```

Это важно: Handy можно использовать не только вручную через собственный hotkey, но и привязать к внешним shortcut managers, scripts или desktop automation.

## Как можно использовать

### 1. Системная диктовка вместо набора текста

Основной сценарий:

```text
hotkey
  ↓
говорим
  ↓
локальное STT
  ↓
текст появляется в текущем приложении
```

Подходит для браузера, ChatGPT, мессенджеров, редакторов, терминальных UI и других приложений, где много текста удобнее диктовать.

### 2. Голосовой ввод для coding agents

Handy не интегрирован специально с Codex или Claude Code — и в этом как раз его плюс. Для агента он выглядит как обычный ввод с клавиатуры:

```text
голос
  │
  ▼
Handy
  │
  ▼
текст
  │
  ├── Codex
  ├── Claude Code
  ├── ChatGPT
  └── любой другой UI
```

То есть не нужен отдельный speech API или plugin каждого агента.

### 3. Локальная диктовка приватных данных

Поскольку распознавание выполняется локально, Handy особенно интересен там, где нежелательно отправлять аудиозапись стороннему облачному STT-провайдеру.

При этом локальность самого распознавания не отменяет правила конкретного приложения, куда затем вставляется текст: после вставки текст может быть отправлен этим приложением в сеть.

### 4. Сравнение с voice-функциями отдельных приложений

Некоторые инструменты имеют собственную встроенную диктовку. Например, Nodeterm умеет локальную Whisper-диктовку внутри своей terminal workspace.

Handy решает задачу уровнем ниже:

```text
Nodeterm dictation
    └── только внутри Nodeterm

Handy
    └── системный слой → любое приложение
```

Поэтому эти инструменты скорее дополняют друг друга, чем конкурируют напрямую.

## Приватность

Ключевая характеристика проекта — offline-first speech recognition. Согласно документации Handy, аудио обрабатывается локально и не отправляется в cloud STT.

Это делает проект значительно интереснее многих SaaS-диктовщиков, особенно для рабочих сценариев.

Следует, однако, разделять:

- приватность аудио на этапе распознавания;
- приватность текста после его вставки в целевое приложение.

Handy контролирует первое, но не второе.

## Сильные стороны

1. Полностью локальное speech-to-text.
2. MIT License.
3. Cross-platform desktop application.
4. Системный сценарий: работает с любым полем ввода, а не только внутри собственного UI.
5. Несколько STT backends: Whisper и Parakeet.
6. GPU acceleration для Whisper.
7. Простая концепция и небольшой operational footprint для пользователя.
8. CLI позволяет интегрировать Handy с hotkeys и automation.
9. Очень заметная пользовательская база и активная разработка.
10. Архитектура Rust + Tauri подходит для desktop utility лучше тяжёлого Electron-приложения.

## Ограничения и риски

1. Whisper может аварийно завершаться на отдельных Windows/Linux конфигурациях; upstream прямо перечисляет это как major known issue.
2. На Linux/Wayland требуется дополнительная настройка text injection (`wtype`, `dotool`, `ydotool` и т. п.).
3. Global shortcuts на Wayland могут потребовать настройки средствами desktop environment/window manager.
4. На macOS использование Bluetooth headset microphone может ухудшать качество воспроизведения во время записи из-за переключения Bluetooth profile.
5. Для вставки текста приложение требует OS-level microphone/accessibility permissions.
6. Локальный STT потребляет CPU/GPU/RAM; крупная Whisper-модель не бесплатна с точки зрения ресурсов.
7. 147 открытых issues на момент добавления показывают, что при высокой популярности проект всё ещё активно дорабатывается.

## Практический тест

Для Windows тест очень простой:

1. Установить Handy из GitHub Release или через Winget.
2. Начать с Whisper Turbo либо Parakeet V3.
3. Настроить удобный push-to-talk hotkey.
4. Проверить русский текст в:
   - браузере;
   - ChatGPT;
   - Telegram;
   - VS Code;
   - Codex/Claude Code UI, если используются.
5. Проверить задержку от отпускания hotkey до появления текста.
6. Проверить качество на длинной технической диктовке: английские термины, названия продуктов, команды и аббревиатуры.
7. Проверить dictionary для часто используемых технических терминов.
8. Сравнить Whisper и Parakeet по качеству русского языка, задержке и нагрузке.

## Что измерить

При практическом тесте полезно зафиксировать:

| Метрика | Что смотреть |
|---|---|
| Latency | время от конца фразы до появления текста |
| Accuracy RU | обычная русская речь |
| Technical vocabulary | Codex, Proxmox, Hyper-V, 1С, VLESS и т. п. |
| Mixed language | русская фраза с английскими терминами |
| Resource usage | CPU / GPU / RAM |
| Hotkey ergonomics | удобно ли использовать весь день |
| Text insertion | корректно ли вставляет текст в разные приложения |

## Пересечения с другими проектами радара

### Nodeterm

Nodeterm имеет собственную локальную диктовку для terminal/agent workspace. Handy интереснее как системный voice-input layer для всех приложений.

### FreeToken

Прямой зависимости нет. FreeToken локально запускает LLM, Handy локально выполняет STT. Вместе они могут быть частью полностью локальной voice-to-agent цепочки:

```text
voice
  ↓
Handy / local STT
  ↓
Codex / OpenCode
  ↓
FreeToken / local LLM
```

### nativeprompt

Handy отвечает за способ ввода текста, nativeprompt — за последующую адаптацию prompt под конкретную модель/agent CLI. Теоретически их можно использовать последовательно.
