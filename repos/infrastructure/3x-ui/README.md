# 3x-ui

> https://github.com/MHSanaei/3x-ui

## Кратко

`3x-ui` — open-source веб-панель для управления серверами на базе Xray-core. Она закрывает не только создание VLESS/VMess/Trojan-подключений, но и управление пользователями, лимитами, статистикой, подписками, маршрутизацией, несколькими узлами и частью эксплуатационных задач.

Проект вырос из X-UI и сейчас представляет собой самостоятельную развитую панель вокруг Xray-core. На момент добавления в Repo Radar репозиторий активно поддерживается, имеет около 45 тыс. stars и 8,6 тыс. forks; основной язык — Go, лицензия — GPL-3.0.

## Какую проблему решает

Xray-core предоставляет мощный транспортный и routing-движок, но его конфигурация вручную быстро становится неудобной, особенно когда появляются несколько inbound'ов, пользователи, сроки действия, квоты и несколько серверов.

`3x-ui` добавляет над Xray управляемый слой:

```text
пользователь / администратор
          │
          ▼
       3x-ui
          │
    ┌─────┼──────────────┐
    │     │              │
 clients routing      statistics
    │     │              │
    └─────┴──────┬───────┘
                 ▼
              Xray-core
                 │
        ┌────────┼────────┐
        ▼        ▼        ▼
      VLESS    Trojan   WireGuard / ...
```

## Основные возможности

### Протоколы и транспорты

Поддерживаются, среди прочего:

- VLESS;
- VMess;
- Trojan;
- Shadowsocks;
- WireGuard;
- Hysteria2;
- HTTP;
- SOCKS / Mixed;
- Tunnel / Dokodemo-door;
- TUN.

Из транспортов и механизмов безопасности доступны TCP/Raw, WebSocket, gRPC, HTTPUpgrade, XHTTP, TLS, XTLS и REALITY.

### Управление клиентами

Для клиентов можно задавать:

- лимиты трафика;
- дату окончания доступа;
- IP limits;
- отслеживание online status;
- share links;
- QR-коды;
- подписки.

Есть статистика по inbound, client и outbound.

### Multi-node

Панель поддерживает управление несколькими узлами. Это делает 3x-ui интересным не только как GUI для одиночного VPS, но и как управляющий слой небольшой распределенной инфраструктуры.

### Routing и outbound

Поддерживаются:

- routing rules;
- load balancing;
- outbound proxy chaining;
- WARP;
- NordVPN;
- пользовательские outbound-конфигурации.

### Subscription server

Встроен сервер подписок с несколькими форматами вывода и возможностью кастомизации страниц подписки.

### Telegram bot

Есть Telegram bot для удаленного мониторинга и части операций управления.

### REST API

Проект предоставляет RESTful API. Swagger-документация доступна непосредственно в панели. Это принципиально важно для автоматизации: инфраструктурные инструменты не обязаны управлять 3x-ui через GUI.

## Хранение данных

Поддерживаются два backend'а:

### SQLite

Используется по умолчанию:

```text
/etc/x-ui/x-ui.db
```

Подходит для простого одиночного развертывания.

### PostgreSQL

Поддерживается как штатный backend и рекомендуется upstream для большого числа клиентов и multi-node setups.

Предусмотрена команда миграции существующей SQLite-базы в PostgreSQL:

```bash
x-ui migrate-db --dsn "postgres://..."
```

## Развертывание

### Обычная установка

Upstream предоставляет install script и CLI-меню `x-ui` для управления сервисом.

### Unattended / cloud-init

Есть неинтерактивная установка через `XUI_NONINTERACTIVE=1`. Результаты установки, включая сгенерированные параметры, сохраняются в `/etc/x-ui/install-result.env`.

Это делает 3x-ui пригодным для воспроизводимого provisioning через cloud-init и инфраструктурную автоматизацию.

### Docker

Есть Docker deployment. По умолчанию используется SQLite; PostgreSQL можно включить через compose profile.

Для полноценной работы Fail2ban внутри контейнера требуются capabilities `NET_ADMIN` и `NET_RAW`.

## Поддерживаемые платформы

Upstream заявляет широкий список Linux-дистрибутивов, включая Ubuntu, Debian, Fedora, RHEL, Rocky Linux, AlmaLinux, Alpine, Arch и openSUSE, а также Windows.

Архитектуры включают `amd64`, `386`, `arm64`, несколько ARM-вариантов и `s390x`.

## Как можно использовать

### 1. Панель управления Xray на публичном VPS

Базовый сценарий:

```text
Internet
   │
   ▼
public VPS
   │
   ├── 3x-ui
   │     │
   │     ▼
   │   Xray-core
   │
   └── reverse proxy / gateway services
```

Панель позволяет централизованно управлять клиентами и transport-конфигурациями вместо ручного редактирования Xray JSON.

### 2. Как API-managed инфраструктурный компонент

Благодаря REST API 3x-ui можно рассматривать как сервис, которым управляют Ansible, Terraform/OpenTofu или собственные automation scripts.

В upstream README отдельно указан community Terraform provider для управления inbound'ами, клиентами, настройками панели и Xray configuration as code.

```text
Git / IaC
   │
   ▼
Ansible / Terraform / scripts
   │
   ▼
3x-ui API
   │
   ▼
Xray-core
```

Это значительно лучше ручного изменения конфигурации через web UI, если инфраструктура должна быть воспроизводимой.

### 3. Multi-node gateway

При нескольких VPS 3x-ui можно использовать как единый управляющий слой поверх нескольких Xray nodes, а PostgreSQL — как более подходящий backend для такого сценария.

### 4. Лаборатория новых Xray transport'ов

3x-ui быстро добавляет новые механизмы Xray, включая XHTTP и современные варианты REALITY/TLS. Поэтому панель удобна как тестовый стенд перед формализацией конфигурации в automation.

## Сильные стороны

1. Очень активный и популярный проект.
2. Широкая поддержка Xray protocols/transports.
3. Хорошее управление клиентами, квотами и сроками.
4. Multi-node support.
5. REST API и Swagger.
6. SQLite и PostgreSQL.
7. Docker и unattended/cloud-init deployment.
8. Встроенный subscription server.
9. Fail2ban integration.
10. Возможность перейти от ручного GUI к инфраструктуре как коду.

## Ограничения и риски

1. Upstream прямо указывает, что проект предназначен для personal use и не рекомендует использовать его в production environment. Это нужно учитывать при проектировании критичной инфраструктуры.
2. 3x-ui управляет Xray, поэтому ошибка в панели или конфигурации может затронуть весь сетевой доступ через соответствующий узел.
3. Web-панель является дополнительной attack surface; ее нельзя без необходимости публиковать напрямую в Internet.
4. Credentials, API access, TLS и backup базы должны рассматриваться как полноценные секреты инфраструктуры.
5. `curl | bash` удобен для первичной установки, но для управляемого deployment предпочтительнее фиксировать версию и автоматизировать установку воспроизводимым способом.
6. Новые Xray transports и параметры меняются быстро; конфигурации необходимо сверять с текущей документацией.
7. GPL-3.0 требует учитывать условия лицензии при распространении модифицированной версии.

## Практический подход

Для устойчивой эксплуатации предпочтительна модель:

```text
             Git repository
                  │
          desired configuration
                  │
          ┌───────▼────────┐
          │ automation/IaC │
          └───────┬────────┘
                  │ API
                  ▼
               3x-ui
                  │
                  ▼
              Xray-core
```

Web UI при этом остается административным и диагностическим интерфейсом, а не единственным источником конфигурации.

## Решение

**Использовать и развивать автоматизацию вокруг него.** 3x-ui — полноценный основной компонент для управления Xray-инфраструктурой. При этом manual-first подход через GUI лучше постепенно заменять на контролируемые API/IaC workflows, а web-панель — защищать как административный интерфейс.
