## Кратко

AI Factory — CLI и набор skills для настройки процессов разработки с coding agents в существующем проекте. Он устанавливает skills, может настраивать MCP и предлагает workflow от исследования и плана до реализации и проверки. Это framework поверх агентных CLI, а не терминальный workspace. Работу CLI мы не запускали.

## Какую проблему решает

Снижает ручную работу по настройке контекста и повторяемых правил для разных coding agents. Ценность для конкретного проекта зависит от того, насколько предсказуемо инструмент меняет локальные agent-конфиги и сохраняет пользовательские настройки при обновлении.

## Основные возможности

- `ai-factory init` для выбора agents, skills и MCP;
- набор skills для исследования, планирования, реализации, исправлений и проверки;
- установка agent-specific файлов и адаптация путей под разные CLI;
- обновление установленных компонентов и расширения;
- документированная проверка скачанных сторонних skills перед использованием.

Перечислено по upstream-документации; корректность gates и качество результата не проверялись.

## Архитектура

`package.json` описывает Node CLI с исполняемым файлом `bin/ai-factory.js`. `init` записывает skills и настройки в agent-specific каталоги проекта; `.ai-factory.json` хранит состояние установки. В документации отдельно описаны управляемые файлы Codex, включая `.codex/config.toml`. MCP-серверы не являются собственным backend AI Factory: CLI настраивает подключения для поддерживаемых agents.

## Как можно использовать

Создать одноразовый тестовый проект и сравнить состояние до/после `init`, повторного `init` и `update`: какие skills и конфиги появились, что изменилось в существующих файлах и как обрабатываются локальные правки. Затем провести одну маленькую задачу с планом и проверкой.

## Интеграции

Документация перечисляет Claude Code, Codex CLI/app, OpenCode и другие coding agents. Автонастройка MCP поддерживается не одинаково для всех agents; список и пути приведены в `docs/getting-started.md`. Через конфигурацию доступны шаблоны GitHub, PostgreSQL, filesystem и browser tooling; реальное подключение здесь не проверялось.

## Развертывание и требования

`package.json` требует Node.js 18+. README предлагает глобальную установку через npm или mise. `init` изменяет файлы проекта и может получать сторонние skills, поэтому применять его только в чистом тестовом проекте после проверки пакета, скриптов и запрашиваемых прав. Никакие команды установки мы не выполняли.

## Сильные стороны

- описаны различия путей и форматов для нескольких agents;
- есть документация по конфигурации, обновлениям и сохранению локальных изменений;
- workflow и quality gates представлены как отдельные, проверяемые шаги;
- безопасность внешних skills рассмотрена в отдельном документе.

## Ограничения и риски

- инструмент потенциально меняет `.codex/`, `.agents/`, `.claude/` и MCP-конфигурацию; до принятия нужен точный diff на тестовом проекте;
- описанный двухуровневый scanner внешних skills — заявление upstream, не результат нашей security-проверки;
- для Codex bundled agent files описаны как базовый слой, без полного паритета с Claude bundle;
- README и `package.json` заявляют MIT, но на зафиксированном commit отдельного файла `LICENSE`/`LICENCE` в дереве нет; условия распространения пакета и юридическую полноту текста нужно уточнить до внедрения;
- update и сторонние extensions требуют отдельной оценки доверия и rollback.

## С чем пересекается

С `OpenAgentsControl` пересекается по стандартизации работы coding agents, но AI Factory ориентирован на установку skills/конфигов и поддержку нескольких agent runtimes, тогда как OAC строится вокруг OpenCode и project patterns. С `agent-skills/mattpocock-skills` пересекается на уровне отдельных skills, но охватывает и установку интеграций.

## Практический тест

На чистом disposable Git-репозитории зафиксировать baseline; после локальной проверки npm-пакета выполнить `init` только для одного agent без реальных credentials; сравнить diff и пути файлов, повторить `init`, изменить один skill вручную и проверить, сохраняет ли `update` правку. Проверить запрет или подтверждение подозрительного стороннего skill в отдельной изоляции. Не запускать это в рабочем проекте первым опытом.

## Итоговая оценка

**7/10 — предварительная оценка по документации.** Плюсы: широкий охват coding agents, подробные правила установки и обновления, skills/MCP и описанные quality gates. Сдерживающие факторы: изменения нескольких agent-конфигов, зависимость от внешних skills, непроверенные security gates и отсутствие отдельного license-файла при заявлении MIT в README и `package.json`. Балл не означает, что CLI уже проверен практически.
