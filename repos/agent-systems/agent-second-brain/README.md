## Кратко

Это персональный Telegram-бот для захвата голосовых, текстовых и других сообщений в Obsidian vault. Его основная роль — агентная система управления знаниями, а не рабочее пространство для coding agents. По документации обработку выполняет постоянная интерактивная сессия Claude Code на собственном сервере. Развертывание и работа здесь не проверялись.

## Какую проблему решает

Позволяет отправлять заметки через привычный чат и сохранять их как связанные Markdown-записи без ручной раскладки по папкам. Практический вопрос для оценки: удаётся ли затем находить нужные записи и поддерживать их качество без потери контроля над личными данными.

## Основные возможности

- приём сообщений через Telegram, включая голосовые;
- транскрибация голоса через Deepgram;
- сохранение материалов в локальном Obsidian vault;
- связи между карточками, напоминания и периодическая обработка записей;
- пользовательский доступ по списку Telegram ID в конфигурации.

Это возможности, описанные авторами в README и настройках; качество их работы не подтверждено нашим запуском.

## Архитектура

Документация описывает цепочку `Telegram → Python bot → постоянная Claude Code session в tmux → Markdown vault`. Отдельные процессы обслуживают напоминания и восстановление сессии. `pyproject.toml` подтверждает Python-пакет и зависимости `aiogram`, `deepgram-sdk`, `pydantic` и другие. Obsidian здесь выступает форматом/интерфейсом хранилища, а не обязательным серверным API.

## Как можно использовать

Проверить на отдельном пустом vault как личный inbox для коротких голосовых заметок, затем оценить качество поиска, связей и напоминаний. Рабочие и клиентские данные использовать только после отдельной проверки доступа, хранения и резервного копирования.

## Интеграции

- Telegram Bot API — ввод и ответы;
- Deepgram API — распознавание голоса;
- Claude Code — агентная обработка;
- Obsidian vault / Markdown — долговременные данные;
- дополнительные возможности Claude Code через skills и MCP заявлены upstream, но не проверены здесь.

## Развертывание и требования

`pyproject.toml` требует Python 3.12+. VPS guide описывает Ubuntu 22.04+, `tmux`, Claude CLI, Telegram bot token, Deepgram API key и локальный vault; для VPS указаны минимум 1 ГБ RAM и рекомендуемые 2 ГБ. Установочные scripts и сервисы мы не запускали. Перед исполнением `setup.sh`/`bootstrap.sh` нужно просмотреть их на выбранном commit и понять создаваемые сервисы и права.

## Сильные стороны

- vault остаётся набором Markdown-файлов под контролем владельца;
- хорошо описаны схема работы и пошаговая установка;
- есть отдельный файл `LICENSE` с текстом MIT;
- пример конфигурации предусматривает список разрешённых Telegram ID.

## Ограничения и риски

- голос, заметки и токены проходят через несколько сервисов; нужны проверка потоков данных и резервного копирования vault;
- значение `ALLOW_ALL_USERS` и пустой список разрешённых ID требуют внимательной настройки; доступ нельзя оставлять открытым по ошибке;
- постоянная сессия Claude Code, внешняя транскрибация и VPS увеличивают эксплуатационную нагрузку;
- заявление автора о способе тарификации Claude не проверялось и может меняться; его нельзя принимать как гарантию стоимости или условий использования;
- security advisories, реальные права сервисов и восстановление после сбоя не проверялись.

## С чем пересекается

В текущем Repo Radar нет другой полноценной карточки персональной базы знаний. С `agent-workspaces/nodeterm` пересекается только использование агентных сессий: Nodeterm организует терминалы и coding agents, а этот проект организует личные записи.

## Практический тест

В изолированной среде с тестовыми токенами и пустым vault: отправить голосовую и текстовую заметки, проверить созданные Markdown-файлы, поиск, ограничение доступа чужого Telegram ID, напоминание, перезапуск сервиса и восстановление vault из backup. Перед запуском проверить scripts и политику обработки данных у внешних сервисов.

## Итоговая оценка

**7/10 — предварительная оценка по документации.** Плюсы: ясный сценарий, описанная архитектура, self-hosted Markdown vault, MIT license и доступный план теста. Сдерживающие факторы: зависимость от Telegram, Deepgram и Claude Code, эксплуатация VPS и непроверенная безопасность личных данных. Балл отражает потенциал для указанного сценария, не результат внедрения.

## Решение

**К практическому тесту.** Документации достаточно для изолированного сценария; перед запуском проверить доступ, потоки данных и скрипты установки, затем восстановление записей.
